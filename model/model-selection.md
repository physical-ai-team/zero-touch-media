# 얼굴 검출 모델 선택 과정 (팀원1)

목표: ESP32-S3(XIAO ESP32S3 + OV2640)에서 **빠르고 정확하게** 사람 얼굴이 있는지 판정한다. 라벨은 `face` 하나.
상세 실험 기록은 [experiments.md](experiments.md), 버전별 요약은 [README.md](README.md).

> 단계마다 평가 기준(테스트 사진)이 다르다. **같은 단계 안에서만** 숫자를 비교한다.

## 결정 흐름 한눈에
| 단계 | 한 일 | 결과 |
|---|---|---|
| 0. 후보 고르기 | Edge Impulse 공개 프로젝트 8개 중 조건에 맞는 것 선택 | public/96468 (FOMO, 96×96 흑백) |
| 1. Edge Impulse 개선 | 학습 설정·입력 크기·모델 폭을 바꿔 6개 비교 | E3 (64×64), v18 |
| 2. 로컬 학습 | 학습 시간 소진 → 다양한 사진(WIDER FACE)으로 직접 학습 | L3, v19 |
| 3. 보드 실측 | 실제 보드·카메라에서 확인 | v19 크래시 없음, 추론 50ms → **v19 유지** |

## 0단계: 사이트 후보 고르기
Edge Impulse 공개 프로젝트에서 "Face detection"(object detection)을 검색해 8개가 나왔다.

**기준**
- ESP32-S3에서 돌 만큼 작은 모델(FOMO 계열)
- 흑백 입력(컬러보다 가볍다)
- 라벨이 `face` 하나
- 바로 복제·배포 가능

| 후보 | 구조·입력 | 데이터 | 판단 |
|---|---|---|---|

| Developer Relations / Face detection - FOMO - bigger dataset (public/116394) | FOMO MNv2 0.35, 96×96 컬러 | FFHQ(수동 라벨, 더 많음) | 탈락. 컬러에 모델 폭 0.35라 더 무겁다. 데이터가 많은 장점은 우리 재학습으로 대신 |

| Edge Impulse Experts / Face detection for AI Bell | – | – | 이름만 봄. 특정 장치용 |

**한계:** 상세 페이지까지 비교한 것은 2개(96468, 116394)뿐이다. 후보끼리 같은 사진으로 정확도를 재지는 않았다. 정확한 표현은 "조건에 맞는 가장 가벼운 후보를 골라 개선했다"이다.

## 1단계: Edge Impulse에서 개선 (96468 복제본)
- 평가: Edge Impulse 테스트셋(FFHQ 정면 사진 88장, 얼굴 137개). F1은 float32 값이다.
- 추정 속도·RAM: Edge Impulse의 **ESP-EYE(구형 ESP32 240MHz) 추정치**로, 상대 비교용이다. 대상 장치 설정은 추정치 계산에만 쓰이고 모델 자체는 바꾸지 않는다. 실제 S3 보드는 더 빠르다.

| 실험 | 입력 | 모델 | 바꾼 것 | F1 | 정밀도 / 재현율 | 추정 속도 | RAM | 결과 |
|---|---|---|---|---|---|---|---|---|
| E0 공개 원본 (v17) | 96×96 | MNv2 0.1 | 원본 그대로 | 0.69 | 0.87 / 0.57 | 728ms | 240K | 얼굴을 자주 놓침 |
| E1 | 96×96 | MNv2 0.35 | 큰 모델(원본 프로젝트의 다른 실험) | 0.71 | 0.60 / 0.87 | 1075ms | 244K | 오탐 많고 느림 |
| E2 | 96×96 | MNv2 0.1 | 학습률 0.00015→0.001 + 증강 | 0.80 | 0.81 / 0.79 | 797ms | 119K | 원본은 학습이 부족했던 것 |
| **E3 (v18)** | **64×64** | MNv2 0.1 | E2 + 입력 축소 | **0.82** | 0.81 / 0.83 | **280ms** | **69K** | **1단계 채택** |
| E4 | 96×96 | MNv2 0.35 | E1 + 학습률↑ + 증강 | 0.80 | 0.93 / 0.69 | 990ms | 115K | 3.5배 느림 → 탈락 |
| E5 | 48×48 | MNv2 0.1 | 입력 더 축소 | 0.77 | 0.80 / 0.74 | 269ms | 52K | 4%만 빨라지고 정확도 하락 |

**판단:** 0.80과 0.82는 테스트 사진이 적어(88장) 사실상 같은 수준이다. 승부를 가른 것은 속도와 메모리다. E3는 원본 대비 2.6배 빠르고 RAM은 약 1/3.5이다.

## 2단계: 로컬 학습 (Edge Impulse 무료 학습 시간 소진 후)
- 평가: WIDER FACE 검증 사진에서 만든 64×64 흑백 5,105장(얼굴 4,132개).
- 방식: Edge Impulse Arduino 라이브러리를 **PC에서 통째로 실행**(전처리·FOMO 후처리 포함, `model/train/pc_harness/`).
- 학습: WIDER FACE 41,067장(`model/train/build_dataset.py`). 얼굴이 화면의 15~55%인 장면이다.

| 모델 | 바꾼 것 | F1 | 정밀도 / 재현율 | PC 추론 | 크기 | 결과 |
|---|---|---|---|---|---|---|
| E3 (v18) | 기준선 (EON 컴파일) | 0.642 | 0.66 / 0.62 | 9.9ms | – | 정면 사진으로만 배워 다양한 사진에서는 떨어짐 |
| L1 | MNv2 0.35 ImageNet 사전학습, 얼굴 가중치 100 | 0.51\* | 0.34 / 0.98 | – | – | 오탐 과다 |
| L2 | MNv2 0.1 처음부터, 얼굴 가중치 100 | 0.53\* | 0.36 / 0.98 | – | – | 오탐 과다 |
| **L3 (v19)** | MNv2 0.1 처음부터, **얼굴 가중치 10**, 가려진 얼굴 무시 | **0.748** | 0.74 / 0.76 | **4.4ms** | 41KB | **2단계 채택** |

\* 변환 전(float) 값이다. 저장에 실패해 int8로는 재지 못했다.

**판단:** 같은 기준에서 F1 0.642→0.748, 추론 시간은 절반이다. 놓침과 오탐이 둘 다 줄었다. 얼굴 가중치 100(Edge Impulse 기본)은 우리 데이터에서 오탐이 너무 많았다.

## 3단계: 보드 실측 (XIAO ESP32S3 + OV2640, ESP32 코어 3.3.12)
| 모델 | 엔진 | 빌드 | 크래시 | 전처리 / 추론 | 정면 50~80cm | 아주 가까운 얼굴 | 얼굴 없을 때 오탐 |
|---|---|---|---|---|---|---|---|
| v17 공개 원본 | EON | 성공 | **추론 중 메모리 손상 → 재부팅 반복** | – | – | – | – |
| **v19 (L3)** | TFLite Micro | Flash 694KB(20%), RAM 40.7KB(12%) | **없음** | **2 / 50ms** (카메라 포함 약 6fps) | 감지 (점수 0.64~0.79) | **못 잡음** | 아직 미측정 |

**판단: v19 유지.**
- v17(EON)은 크래시가 났고 v19(TFLite Micro)는 정상이다. 둘 다 ESP-NN을 켠 상태라 원인은 EON 쪽으로 좁혀진다. v18도 EON이라 같은 위험이 있다.
- 추론 50ms면 실시간 판정에 충분하다.

## 남은 일
- **가까운 얼굴(화면 가득) 보완:** 학습 데이터 얼굴 크기를 15~55%에서 15~90%로 넓혀 재학습한다(v20). 메모리 크기와 임계값을 v19와 같게 두면 모델 파일 하나만 바뀌어 재컴파일이 짧다.
- **실제 정확도 측정(팀원4):** `model/testing/measure.py`로 상황 11개의 감지율과 오탐률을 잰다. 특히 얼굴이 없을 때의 오탐률.
- **예비안:** v19가 시연 카메라에서 성능이 나쁘면 Espressif의 학습된 얼굴 검출 모델(esp-dl)을 검토한다. 단, 코어를 2.0.x로 내리고 펌웨어를 다시 이식해야 한다.
